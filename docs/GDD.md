## 3. 移动系统设计

### 设计参考
- **蔚蓝 (Celeste)** — 精准、宽容的平台跳跃手感
- **奥日 (Ori) 系列** — 流畅的动作衔接与环境交互
- **裤头小子 (Klonoa) 系列** — 独特的平台跳跃机制

### 动作分层架构

移动动作按**优先级**和**确定性**分为两层：

#### 第一层：核心必做（保证基础手感）
| 动作 | 状态 | 完成度 |
|------|------|--------|
| 待机 | `idle` | ✅ 已完成 |
| 奔跑 | `run` | ✅ 已完成 |
| 跳跃 | `airborne` | ✅ 已完成（含 coyote time / jump buffer / 多段跳 / 跳跃截断） |
| 墙滑 | `wall_grab` | ✅ 已实现（墙滑下落速度 20；仅下落中 + 按向墙面进入） |
| 墙跳 | `wall_jump` | ✅ 已实现（蹬墙水平速度 300；空中贴墙按跳优先于土狼跳） |
| 边缘挂边 | `ledge_grab` / `ledge_slide` / `ledge_climb` | ✅ 已实现（挂边/滑落/上爬，见 ROADMAP 1.6；动画占位） |

#### 第二层：可选扩展（预留接口，按需启用）
| 动作 | 状态 | 完成度 | 备注 |
|------|------|--------|------|
| 墙踢 | `wall_kickout` | ✅ 已实现 | 蹬墙离墙，水平速度 200 |
| ~~墙攀~~ | ~~`wall_climb`~~ | ❌ 已放弃 | 2026-08-16 决策；代码已删除，动画帧保留备用 |
| 滑铲/刹车 | `slide` | 🔄 归类至 M2 | 职责为"结束移动的刹车脚本"，随 M2 动作衔接开发（含触发接线） |
| 冲刺/闪避 | [待定] | ❌ 未开始 | 可能与战斗闪避合并 |
| 二段跳 | [待定] | ⚠️ 已实现 | `extra_air_jumps` 默认 1，视关卡设计需要决定是否保留 |
| 抓钩/摆荡 | [待定] | ❌ 未开始 | 奥日风格，远期 |

> **架构原则**：所有移动状态继承自 `00_player_state.gd` 基类，通过状态机切换。新增动作只需新建状态文件并注册，无需改动核心逻辑。核心层：idle / run / airborne / wall_grab / wall_jump / wall_kickout / ledge_grab / ledge_slide / ledge_climb。

### 动作衔接动画（后续阶段）
所有动作之间添加**过渡动画**（如起跑、落地、起身），避免生硬切换。在移动动作全部定稿后统一制作。

## 4. 战斗系统设计

### 设计参考

- **怪物猎人 (Monster Hunter)** — 派生动作模组，武器动作树

### 核心设计
- **武器**：一把刀从头用到尾，不做武器切换
- **道具**：轻量道具系统（恢复、辅助等）

## 5. 美术风格

### 参考
**合金弹头 (Metal Slug) 系列**
- 流畅的动画（高帧率、关键帧丰富）
- 夸张的动作表达
- 丰富的场景细节与互动元素

### 当前资源
- 像素风格角色精灵（Aseprite 工作流）
- 调试用 tileset（debug_bricks）

### 动画工作流
```
完成动作程序逻辑 → Aseprite 制作动画 → 导入 Godot → 代码调试动画同步 → 迭代
```
动画与动作**同步推进**，不做"先全部写完代码再补动画"。

## 6. 相机系统

### 相机导演系统（计划中）
相机不固定跟随角色，而是**预测性偏移**：
- 左右移动时：向移动方向偏移
- 向上移动/跳跃时：向上偏移
- 向下移动/坠落时：向下偏移
- 环境因素：特定区域/事件触发相机运动（如 Boss 战、过场）

### 开发时机
移动系统基本完成后开始。

## 7. 技术架构

### 项目结构
```
PROJECT_INDEX.md         # 项目管理文件索引
Game_Build/              # Godot 工程（仓库子目录）
├── addons/              # 插件（debug_system）
├── assets/game/         # 游戏资源（角色、tileset）
├── dev_tools/           # 开发工具（AI 助手）
├── player/              # 玩家相关
│   ├── scripts/         # 核心脚本
│   ├── states/          # 状态机状态
│   ├── sprites/         # 精灵
│   └── audio/           # 音频
├── playground.tscn      # 测试主场景
└── project.godot
docs/                    # 设计文档（本文件所在）
├── GDD.md               # 游戏设计文档
├── ROADMAP.md           # 开发路线图
└── devlog/              # 开发日志（按日期命名，如 2026-08-16.md）
Source_Files/            # 美术源文件（Aseprite）
```

### 关键系统
- **状态机**：玩家移动/战斗统一状态管理
- **DebugManager**：自动加载的调试管理器（F 键等快捷键）
- **AI 助手**：编辑器内 DeepSeek 集成面板

### 命名规范 `[待统一]`
- 脚本：snake_case（如 `player.gd`、`wall_climb.gd`）
- 状态文件：已有 `00_` / `01_` 数字前缀，建议统一为纯名称或统一前缀
- 资源：snake_case（当前存在 `Player.png` 与 `player.png` 混用，需统一）
