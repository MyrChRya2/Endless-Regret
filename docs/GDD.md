## 3. 移动系统设计

### 设计参考
- **蔚蓝 (Celeste)** — 精准、宽容的平台跳跃手感
- **奥日 (Ori) 系列** — 流畅的动作衔接与环境交互
- **裤头小子 (Klonoa) 系列** — 独特的平台跳跃机制

### 动作分层架构

移动动作按**优先级**和**确定性**分为两层：

#### 第一层：核心必做（保证基础手感）
| 动作 | 状态 | 完成度 |
|------|------|--------|
| 待机 | `idle` | ✅ 已完成 |
| 奔跑 | `run` | ✅ 已完成 |
| 跳跃 | `airborne` | ✅ 已完成 |
| 滑铲 | `slide` | ✅ 已完成 |
| 墙滑 | `wall_state` | 🔄 进行中 |
| 墙跳 | `wall_jump` | 🔄 进行中 |

#### 第二层：可选扩展（预留接口，按需启用）
| 动作 | 状态 | 完成度 | 备注 |
|------|------|--------|------|
| 墙攀 | `wall_climb` | 🔄 原型中 | 消耗体力/耐力，可后期加入 |
| 墙抓 | `wall_grab` | 🔄 原型中 | 贴墙停顿，可作为墙攀前置 |
| 墙踢 | `wall_kickout` | 🔄 原型中 | 蹬墙后跳，高级技巧 |
| 冲刺/闪避 | [待定] | ❌ 未开始 | 可能与战斗闪避合并 |
| 二段跳 | [待定] | ❌ 未开始 | 视关卡设计需要 |
| 抓钩/摆荡 | [待定] | ❌ 未开始 | 奥日风格，远期 |

> **架构原则**：所有移动状态继承自 `00_player_state.gd` 基类，通过状态机切换。新增动作只需新建状态文件并注册，无需改动核心逻辑。当前已有的 wall_climb / wall_grab / wall_kickout 作为扩展原型保留，不强制进入核心循环。

### 动作衔接动画（后续阶段）
所有动作之间添加**过渡动画**（如起跑、落地、起身），避免生硬切换。在移动动作全部定稿后统一制作。

## 5. 美术风格

### 参考
**合金弹头 (Metal Slug) 系列**
- 流畅的动画（高帧率、关键帧丰富）
- 夸张的动作表达
- 丰富的场景细节与互动元素

### 当前资源
- 像素风格角色精灵（Aseprite 工作流）
- 调试用 tileset（debug_bricks）

### 动画工作流
```
完成动作程序逻辑 → Aseprite 制作动画 → 导入 Godot → 代码调试动画同步 → 迭代
```
动画与动作**同步推进**，不做"先全部写完代码再补动画"。

## 6. 相机系统

### 相机导演系统（计划中）
相机不固定跟随角色，而是**预测性偏移**：
- 左右移动时：向移动方向偏移
- 向上移动/跳跃时：向上偏移
- 向下移动/坠落时：向下偏移
- 环境因素：特定区域/事件触发相机运动（如 Boss 战、过场）

### 开发时机
移动系统基本完成后开始。

## 7. 技术架构

### 项目结构
```
Game_Build/
├── addons/              # 插件（debug_system）
├── assets/game/         # 游戏资源（角色、tileset）
├── dev_tools/           # 开发工具（AI 助手）
├── player/              # 玩家相关
│   ├── scripts/         # 核心脚本
│   ├── states/          # 状态机状态
│   ├── sprites/         # 精灵
│   └── audio/           # 音频
├── docs/                # 设计文档（本文件所在）
├── playground.tscn      # 测试主场景
└── project.godot
```

### 关键系统
- **状态机**：玩家移动/战斗统一状态管理
- **DebugManager**：自动加载的调试管理器（F 键等快捷键）
- **AI 助手**：编辑器内 DeepSeek 集成面板
