## 挂边状态 v1：射线检测方案（2026-08-17 尝试）

### 实现内容（工作区未提交）
- **墙接触分类**：`player.gd` 新增 `WallContact` 枚举（`NONE / FULL / SLIDING / LEDGE_TOP`）+ `classify_wall_contact()`，用三条射线判定：
  - 头顶水平射线（`wall_ray_head_y = -25`，长 20）
  - 脚底水平射线（`wall_ray_feet_y = -2`，长 20）
  - 垂直平台顶射线（`ledge_ray_from_y = -41`，向下 28，要求命中面法线朝上）
  - 组合逻辑：`LEDGE_TOP` = 垂直命中平台顶 ∧ 脚底命中；`FULL` = 头顶 ∧ 脚底都命中；其余 = `SLIDING`
- **状态分发**：`airborne.gd` 贴墙时按分类分发 → `FULL` → `WallGrab`；`LEDGE_TOP` → `LedgeGrab`；`SLIDING` → `LedgeSlide`
- **新状态**：
  - `ledge_grab.gd`：挂边（吸附 `_snap_to_ledge`、按上上扒 `_climb_up`（含头顶空间检测）、蹬墙跳、踢墙、被撞离墙掉落）
  - `ledge_slide.gd`：贴墙滑落（等待挂边条件）
- **调试辅助**：`_draw()` 实机绘制三条判定射线（命中绿/未命中红）+ DebugManager 输出 `wall_contact`

### 效果反馈（本人）
- **效果很差，大概率尝试重构。**

### 失败原因初步分析（射线方案的固有缺陷）
1. **固定像素偏移耦合碰撞盒**：射线起点的局部偏移（-25 / -2 / -41）依赖碰撞盒尺寸与精灵对齐，改碰撞盒即失效。
2. **边缘几何歧义**：墙角、薄平台（< 射线长度）、斜面、紧贴双平台场景下，垂直射线的"平台顶"判定不稳定，易误分类为 SLIDING 或漏判。
3. **速度敏感**：下落速度快时单帧位移大，射线窗口错过边缘；`velocity.y >= 0` 条件与碰撞响应顺序耦合。
4. **分类与 `is_on_wall()` 打架**：`is_on_wall` 是 move_and_slide 的碰撞结果，与射线几何判定存在时序差，边缘处抖动。

### 重构方向候选（待本人决策）
- **A. Area2D 传感器**：碰撞盒两侧/顶部挂触发区，`body_entered/exited` 事件判定平台顶——无每帧射线成本、对薄平台更稳，是平台跳跃游戏常用方案。
- **B. 基于 move_and_slide 碰撞数据**：直接用 `get_slide_collision()` 的碰撞点/法线做几何判定，射线仅作二次确认。
- **C. 改进射线**（最小改动）：多射线采样 + 帧间插值（前后两帧位移区间内采样）+ 宽容窗口；保留现有 `_draw()` 调试可视化。
- 建议保留 v1 的调试可视化与 `WallContact` 分类思路（架构合理，仅判定手段待换）。
