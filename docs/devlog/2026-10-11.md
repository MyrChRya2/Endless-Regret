## 决策与理由

### 直连优先，代理只做回退（用户口径 + 实测）
实测现在**直连 GitHub 是通的**（HTTPS 200 / 0.9s；SSH 能握手拿到 host key）→ 不长期挂代理，只在直连失败时自动降级走 socks5。理由：代理会引入延迟与额外故障面，而当前的故障只是"没有密钥"。

### 连通性判据改用 SSH banner（被现实纠正）
本机环境下 TCP 层"能连上"是**假信号**（FlClash 会把任意远端 IP:port 的连接立即接受），因此：
- ❌ 判据 A：`nc -z -w 3 host port` —— 实测对 `192.0.2.1:22`（保留测试网段，必然不可达）**报成功**；
- ❌ 判据 B：bash `exec 3<>/dev/tcp/host/port` —— 同样误报成功；
- ✅ 判据 C：**读到对端 banner**（`head -c 64 <&3` 拿到 `SSH-2.0-…`）——实测能正确区分（github 有 banner、`192.0.2.1` 空）。
- 本机地址（`127.0.0.1`、NAT 网关）的 TCP 探测仍可靠，所以"代理端口是否在听"仍用普通探测。

### 不推送，等用户确认
按值班室口径：`fetch` 通过前不下"领先 N 笔"的结论、**也不 push**。本日只把链路修好并核实差距，推送时机交给用户（属对外动作）。

## 踩坑 / 问题

- **坑 1（新发现，已写入 skill）**：`nc -z` / `/dev/tcp` 在本机对**任意远端 IP 都报成功**（FlClash 透明拦截）→ 不能用 TCP 连通当网络判据；只有 banner（或真实应用层握手）算数。
- **坑 2**：WSL 里 `~/.gitconfig` 根本不存在——Windows 侧的 user / socks5 代理 / safe.directory / GCM **都没迁过来**，所以 10-10 那两笔提交的作者是 `-c` 临时传的。已补齐全局身份。
- **坑 3**：`Permission denied (publickey)` 曾被当成"网络问题"——实际是 **known_hosts 有、私钥无**，属认证问题。预检口诀：**publickey 拒绝＝认证；卡住/超时＝网络**。
- **未完成**：FlClash **Allow LAN 未开**（实测默认网关 `172.23.48.1` 的 7890/1080/10809/7897 全不通）→ 代理分支当前不可用；已在脚本里做好降级（回退直连并打印诊断），并备好 mirrored 方案。
