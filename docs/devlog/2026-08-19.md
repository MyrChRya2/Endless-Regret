## 决策与理由

- **挂边判定用"高度 + 法线"双判据** → 凸分解斜边的高度恰好能骗过纯高度判据（墙角场景挂边误判根源）；法线过滤（normal.y < -0.9）只认水平墙顶
- **LedgeSlide 限速 120** → 原"保持重力"决策被数据推翻：无限加速会让一帧下滑超过挂边检测窗口（8px）导致漏判
- **垂直射线偏移 10px（墙内 2px）** → 偏移 12px 会穿透到墙后瓦片（墙角场景）；偏移 < 8px 又打不到墙顶（玩家中心在墙外）
- **挂边需要"从上方足够远处接近"（dy > 12px）** → 坠落/撞墙时头顶已在墙顶附近（dy 小）不应被瞬间抓住
- **判定可视化保留（调试期）** → 判定过程可视化，便于理解射线原理和定位问题

## 踩坑 / 问题

- 垂直射线打在玩家中心 → 玩家中心在墙外 8px（碰撞盒半宽），永远打不到墙顶（水平射线命中/垂直射线不命中的矛盾数据暴露此坑）
- 垂直射线偏移 12px → 墙角/薄墙场景穿透检测到墙后瓦片（挂边误判）
- TileMapLayer 凹形凸分解产生 45° 斜边 → 斜边高度恰好落在挂边容差内，纯高度判据误判挂边（加瓦片改变布局后"问题消失"是定位线索）
- 高速滑落（重力无限加速）→ 一帧跳过挂边窗口 → 垂直射线从不命中
- WallGrab 只查 `is_on_wall()` → 脚底离墙仍慢滑到完全脱墙才自由落体
- GDScript 类型推断：`var x := hit.position`（Dictionary 值是 Variant）报 Cannot infer type；三元运算符 StringName vs String 报 INCOMPATIBLE_TERNARY

## 其他（素材 / 灵感 / 备忘）

- 调试方法论：一组矛盾观测（水平射线命中 / 垂直射线不命中）直接指向"射线打偏"根因——**对照射线**是验证查询管道是否正常的有效工具
- 凸分解斜法线的定位流程：瓦片多边形输出 + 法线精确复现 + `hit.shape` 字段差异，是识别物理引擎行为的标准证据链
- 射线端点位置原则：起点/终点都要在目标表面之外；检测"贴着的墙"时射线起点必须放墙表面/墙体内
